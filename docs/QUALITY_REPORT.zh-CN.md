## 升级前发现的问题

- 导出使用码流复制，起止位置会受视频关键帧影响，实际片段可能比标记范围多出一段。
- 长视频的打点结果只存在内存中，程序退出或异常终止后无法恢复。
- 导出任务没有进度和取消入口，用户无法判断长任务是否仍在运行。
- 单独导出会直接使用固定文件名，已有文件存在时可能被覆盖。
- 播放器在 Qt 真正接受媒体前就把视频标记为已加载，错误文件也可能短暂启用控件。
- 片段数据允许非法范围进入模型；编辑时间时也没有检查是否超出视频长度。
- 只有少量快捷键，筛选、保存、精确编辑和帮助说明不完整。
- 主窗口同时负责数据验证、表格编辑和导出细节，仓库没有测试、安装元数据或发布构建流程。

## 已完成的修复

### 剪辑与导出

- 每个片段按毫秒时间重编码为 H.264/AAC，避免关键帧限制。
- 拼接结果先写入目标目录内的临时文件，完成后再原子替换正式文件。
- 单片段文件名包含安全化标签；文件已存在时自动增加序号。
- FFmpeg 进程支持中止，界面显示逐段进度和取消状态。
- 禁止把拼接结果保存到源视频路径。

### 时间轴与工程

- `VideoSegment` 是不可变、带验证的数据模型。
- 时间轴保留最近 100 个撤销状态。
- `.rallypin.json` 工程文件保存视频路径、时间段和标签；同目录时优先使用相对路径。
- 工程写入使用临时文件和原子替换，防止中途失败损坏已有工程。
- 每次有效时间轴修改都会写恢复副本。重新启动时可以恢复未保存内容。
- 视频移动后可以在打开工程时重新定位。

### 交互与界面

- 播放、快进快退、变速、静音、打点、标签、时间编辑、删除、清空、撤销、筛选和导出都有键盘入口。
- 文本编辑和下拉框获得焦点时，单键播放快捷键会暂时释放，避免输入标签时误操作视频。
- 所有功能同时保留菜单、按钮、表格双击或拖动操作。
- 视频区保持源画面比例，视频与片段表的高度可以用滑块或分隔条调整。

### 工程质量与发布

- 运行时依赖只保留 PyQt6 与 imageio-ffmpeg。
- 添加 `pyproject.toml`、控制台启动命令和 `python -m rallypin` 入口。
- 添加 Ruff 静态检查、22 项自动测试、GitHub Actions 和 Windows 单文件构建。
- 添加 Windows 本地构建脚本、PyInstaller 配置、更新日志和完整 README。

## 验证结果

- Ruff 全仓库静态检查通过。
- Python 源码编译检查通过。
- 22 项自动测试通过。
- 测试会真实生成一段带音频的视频，执行两个片段的精确剪切和拼接，并验证结果文件。
- `pip install -e ".[dev,build]"` 安装通过，包版本为 1.0.0。
- PyInstaller 成功生成 `dist/RallyPin.exe`，程序启动后持续运行，没有立即退出。
- 1280×800 离屏界面渲染检查通过，主要控制区和片段表没有溢出。

## 当前产品边界

- RallyPin 目前依靠用户按键标记回合，不包含自动识别击球或回合的模型。
- GitHub 自动构建的 Windows 程序没有代码签名，首次打开可能出现 SmartScreen 提示。
- 输入视频能否直接播放取决于系统上的 Qt 编解码能力。H.264/AAC MP4 的兼容性最好。
- 一个工程对应一个源视频，暂不支持把多机位或多个文件放入同一时间轴。
- 仓库目前只自动生成 Windows 可执行文件。macOS 和 Linux 用户需要从 Python 源码启动。
- 界面文字目前为英文，README 提供了中文快速说明。
